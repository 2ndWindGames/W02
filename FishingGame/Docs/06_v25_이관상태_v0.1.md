# v25 HTML → Unity 이관 상태

최종 갱신: 2026-09-02  
기준 소스: `HTML_GAME/external/05_변경사항_09에서_v25.md`, `HTML_GAME/external/fish-merged-v25.html`

## 범위

공식 Unity 프로젝트 `FishingGame/Assets/FishingV2`에 v25의 어종 데이터·이동·먹이 반응·획득 규칙을
이식한다. HTML의 DOM·CSS·Three.js 런타임은 이식하지 않고, 실행 가능한 행동 기준과 수치만 사용한다.

실제 플레이 어종은 멸치·연어·만새기·오징어·참치 5종이다. v25의 `needle`·`minnow`·`disc`는
타입 조합 검증용 어종으로 Catalog와 개발용 `Spot_Validation_AllSpecies`에 포함한다.
`Spot_Beach`의 최종 밸런스 기준에는 검증용 어종을 포함하지 않는다.

## 브랜치 경계

행동 이관 브랜치: `codex/fish-movement`  
물 표현 브랜치: `codex/water-presentation`

물 브랜치가 정리될 때까지 다음 파일은 행동 브랜치에서 수정하지 않는다.

- `Scripts/Runtime/BobberV2.cs`
- `Scripts/Runtime/FishingV2Session.cs`
- `Shaders/FishSurfaceV2.shader`
- `Shaders/WaterSurfaceV2.shader`
- `Shaders/WaterOpticsField.hlsl`
- 물 표현 Profile/Director/Menu 파일

물 브랜치가 `main` 또는 공통 기준에 반영된 뒤에만 위 파일을 수동 통합한다. 물 브랜치가 추가한
수면 프로파일, 수중 카메라, ripple 강도, fish water-light 프로퍼티는 덮어쓰지 않는다.

## 2026-09-02 동작 검증 결과

Unity Editor의 격리 Additive 씬에서 고정 timestep 1/60초로 90초를 실행했다. 실제 5종과
검증용 3종을 모두 등록하고, 기본 lure·자동 회수·catch flight·학교 추종을 켠 상태에서
한 번 던지기를 주입했다.

- `errors=0`
- 최대 활성 fish `30`
- validation-only fish 생성 확인 `true`
- `maxVisibleStep=0.2725`
- 화면 안 `visibleLargeJumps=0`
- 종료 score `28` (점수는 lure/catch 랜덤 결과라 이동 판정과 독립)
- Runtime/Editor 콘솔 오류 `0`

이 과정에서 확인된 이동 버그는 세 가지였다. C-start 오프셋이 리더 위치에 프레임마다
중복 적용되던 문제, 수심을 무시한 대형 강제 겹침 보정, 잡힌 학교 리더의 stale reference를
추종자가 독립 경로로 잘못 해석하던 문제다. 각각 `FishAgentV2`의 오프셋 보간·작은 hard
push·수심 게이트·죽은 리더 detach·재앵커링으로 보정했다. 검증 메뉴도 현재 씬을 교체하거나
에디터를 종료하지 않고 임시 Additive 씬만 닫도록 바꿨다.

단, 이 수치는 렌더 프레임 캡처가 아닌 시뮬레이션 연속성 검증이다. 실제 카메라 투영도 별도로
확인했으며, 현재 `FishingV2Session`의 카메라가 `Euler(0,180,0)`인 상태에서 화면 오른쪽
끝의 월드 X가 왼쪽 끝보다 `-19.584`가 된다. 즉 현재 `CastAtScreenPoint`는 화면 오른쪽
입력을 월드 왼쪽으로 변환한다. 낚시대 반대 투척 증상은 재현 조건이 확인된 상태이며,
`FishingV2Session.cs`가 물 브랜치 경계 파일이므로 해당 좌표계 수정은 물 브랜치 머지 때
함께 반영해야 한다.

Unity Editor가 없는 환경에서는 캐시된 Unity 참조 어셈블리로 Runtime/Core 컴파일만 수행할 수 있다.
실제 PlayMode, 메시 색상화, 90초 화면 관찰은 Unity Editor가 설치된 환경에서 수행한다.
