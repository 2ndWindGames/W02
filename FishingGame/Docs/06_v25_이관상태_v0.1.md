# v25 HTML → Unity 이관 상태

최종 갱신: 2026-09-04
기준 소스: `HTML_GAME/external/05_변경사항_09에서_v25.md`, `HTML_GAME/external/fish-merged-v25.html`

## 범위

공식 Unity 프로젝트 `FishingGame/Assets/FishingV2`에 v25의 어종 데이터·이동·먹이 반응·획득 규칙을
이식한다. HTML의 DOM·CSS·Three.js 런타임은 이식하지 않고, 실행 가능한 행동 기준과 수치만 사용한다.

실제 플레이 어종은 멸치·연어·만새기·오징어·참치 5종이다. v25의 `needle`·`minnow`·`disc`는
타입 조합 검증용 어종으로 Catalog와 개발용 `Spot_Validation_AllSpecies`에 포함한다.
`Spot_Beach`의 최종 밸런스 기준에는 검증용 어종을 포함하지 않는다.

## 최종 아트 방향 결정 (2026-09-04)

최종 아트 기준 생성기는 현재 프로젝트의 `FishVisualSpec`/`FishMeshBuilderV2`로 유지한다.
외부 GLB/FBX나 별도 텍스처·본 애니메이션 파이프라인으로 전환하지 않고, 현재의 procedural
3D 메시를 계속 생성·검수한다. stylized 색상, 어종별 실루엣과 과장된 크기 비율, 정점 컬러와
셰이더 기반 움직임도 유지한다.

- 실제 플레이 5종은 현재의 어종별 VisualSpec을 기준으로 계속 생성한다.
- `needle`·`minnow`·`disc`는 검증용 procedural 메시로만 유지한다.
- 로컬 `+X` 진행 방향, 몸 중앙 원점, UV0/UV1 생동감 채널, 공용 `FishSurfaceV2` 셰이더
  계약은 변경하지 않는다.
- 최종 메시 품질은 현재 생성기 출력의 top-down 식별성, 색상 대비, mouth 위치, shadow와
  Catch Flight 재사용을 기준으로 판단한다.
- `Assets/FishingV2/Art/Fish_*.asset`은 생성기 출력의 baked baseline이며, 생성 메뉴로
  갱신한다. 런타임 행동/입질/보상 데이터는 메시 유무와 독립적으로 계속 검증한다.

## 2026-09-04 머지 후 동작 검증 결과

Unity Editor의 격리 Additive 씬에서 고정 timestep 1/60초로 90초를 실행했다. 물 표현 브랜치
머지 후 실제 5종과 검증용 3종을 모두 등록하고, 기본 lure·자동 회수·catch flight·학교 추종을
켠 상태에서 한 번 던지기를 주입했다. 기본 catch 경로와 After-Bite 방생 경로를 별도 메뉴로
실행해 서로의 결과를 섞지 않았다.

기본 catch 경로:

- `errors=0`
- 최대 활성 fish `46`
- validation-only fish 생성 확인 `true`
- `maxVisibleStep=0.3787`
- 화면 안 `visibleLargeJumps=0`
- `strikeFrames=283`
- `hookedFrames=2922`
- `arrivals=18`, `tally=18`
- `respawns=18/18`, `spawned=64`, `initial=46`
- 종료 score `36` (점수는 lure/catch 랜덤 결과라 이동 판정과 독립)
- Runtime/Editor 콘솔 오류 `0`

After-Bite 방생 경로:

- `errors=0`
- 최대 활성 fish `46`
- validation-only fish 생성 확인 `true`
- `maxVisibleStep=0.3977`
- 화면 안 `visibleLargeJumps=0`
- `strikeFrames=488`
- `hookedFrames=2376`
- `afterBiteFrames=160`
- `arrivals=9`, `tally=9`
- `respawns=9/9`, `spawned=55`, `initial=46`
- 종료 score `23`
- Runtime/Editor 콘솔 오류 `0`

이 과정에서 확인된 이동 버그는 세 가지였다. C-start 오프셋이 리더 위치에 프레임마다
중복 적용되던 문제, 수심을 무시한 대형 강제 겹침 보정, 잡힌 학교 리더의 stale reference를
추종자가 독립 경로로 잘못 해석하던 문제다. 각각 `FishAgentV2`의 오프셋 보간·작은 hard
push·수심 게이트·죽은 리더 detach·재앵커링으로 보정했다. 검증 메뉴도 현재 씬을 교체하거나
에디터를 종료하지 않고 임시 Additive 씬만 닫도록 바꿨다.

단, 이 수치는 렌더 프레임 캡처가 아닌 시뮬레이션 연속성 검증이다. 카메라가
`Euler(0,180,0)`이면 월드 +X가 화면 왼쪽에 보이는 것은 의도된 좌표계지만,
`ScreenToWorldPoint`가 그 투영의 역변환을 이미 수행하므로 입력 결과에 X 반전을 추가하면 안 된다.
병합 후 실제 GameView A/B 회귀도 수행했다.

- 화면 오른쪽 클릭(global x=1000) → 오른쪽에 착수 ripple/bobber 표시
- 새 세션에서 화면 왼쪽 클릭(global x=550) → 왼쪽에 착수 ripple/bobber 표시
- 따라서 `CastAtScreenPoint`의 현재 raw `ScreenToWorldPoint` 경로는 정상이며, 낚시대 반대
  투척 문제에 대한 추가 좌표계 수정은 남아 있지 않다.

## 2026-09-07 포폴 HUD 선택 이식

별도 포폴 리포트 `FishingIsGood`의 UI 작업 중 HUD에 필요한 부분만 현재 프로젝트에
선택적으로 이식했다. 원본 전체 UnityProject를 병합하지 않고, 물 표현·게임플레이·검증
코드는 현재 브랜치 버전을 유지한다.

- 원본 기준 커밋: `d0219e1` HUD portrait/Catch Bag 교체, `8653c8b` 어종별 portrait 크기 조정
- 어종 portrait 5종을 `Assets/FishingV2/Art/Hud/`에 추가
- `FishSpeciesConfig.HudIcon`과 `HudIconScale`을 추가하고 실제 5종에 연결
- `FishingV2Session.CatchBagTexture`와 텍스처 Catch Bag을 추가
- 이미지가 비어도 procedural HUD portrait와 primitive Catch Bag으로 동작하는 fallback 유지
- 좁은 GameView에서도 Catch Bag이 잘리지 않도록 카메라 viewport safe area에 배치
- 적용 메뉴: `Fishing V2/Apply HUD artwork`

최신 정상 회귀 캡처는 `Assets/Screenshots/Regression/`에 있으며, HUD portrait와
Catch Bag이 착수·Catch Flight·도착·재생성 화면에서 함께 보이는지 확인했다. 이번 UI
이식은 별도 commit하지 않고 현재 작업 트리에 남겨, 물 merge commit과 UI 변경을 분리해
리뷰할 수 있게 했다.

같은 Unity Editor에서 구조 검증 메뉴도 실행했다. validator는 5개 playable, 3개 validation
어종을 확인하고, 전체 `AfterBiteMode` 값(`Peel/Pass/School/Arc/Jet`)이 카탈로그에 존재하는지와
각 profile의 duration/speed/cooldown 범위를 함께 확인한다.

- `Fishing V2/Validate v25 catalog and mesh channels` → `playable=5`, `validation=3`
- Unity 스크립트 재컴파일 오류 및 구조 검증 중 Runtime/Editor 오류 `0`

추가로 `Strike`는 현재 fish state에 남긴 채 Bobber 콜백으로 전달하고, swept mouth contact는
어종별 mesh 기반 mouth offset을 사용하도록 연결했다. Strike/Hooked 상태가 실제로 관측되는지와
mouth 위치에 찌가 고정되는지까지 smoke test에 명시적으로 기록하도록 계측을 추가했으며, 위
`strikeFrames`/`hookedFrames`가 그 결과다. 자동 회수 후 Hooked fish가
찌 위치로 한 프레임에 이동하던 점프도 `MoveTowards` 상한으로 막았고, 검증 하네스는 파괴된
개체 ID를 다음 개체와 비교하지 않도록 프레임별 active ID만 유지한다.

Catch Flight에는 live fish와 같은 광원 방향·바닥 평면 투영을 적용했다. 비행 중에는 높이에
따라 그림자 알파를 줄이고 softness를 늘리며, fish와 같은 Underwater Render Layer에서 한 번만
렌더한다.

방생 경로의 `After-Bite`는 `FishAgentV2.BeginAfterBite`에서 어종 profile을 샘플링하고, `School`
모드에서는 살아 있는 leader/formation slot을 유지한다. `Jet`은 초기 속도 배율을 높이고,
`Arc`는 진행도에 따른 측면 호를 추가하며, 나머지 `Peel/Pass`는 profile의 이탈 비율과 현재
침로를 조합한다. 완료 후에는 개체별 cooldown으로 roam에 복귀한다.

PlayMode GameView에서도 첫 착수 후 물 연출 → gameplay 전환, 오른쪽/왼쪽 착수 위치, 입질 시
찌 주변 feedback와 Hooked fish 표시를 확인했다. 자동회수 게이지는 Hooked 상태에서 남은
시간에 따라 줄어들고, 찌는 접촉 전 amber에서 입질 직후 밝은 섬광을 거쳐 주황→빨강으로
변한다.

Unity Editor가 없는 환경에서는 캐시된 Unity 참조 어셈블리로 Runtime/Core 컴파일만 수행할 수 있다.
실제 PlayMode, 메시 색상화, 90초 화면 관찰은 Unity Editor에서 수행 완료했다.
