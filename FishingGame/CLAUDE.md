# 낚시 게임 — 프로젝트 지침

> 이 폴더(`FishingGame/`)가 이 작업의 정식 Unity 프로젝트 루트다.
> 상위 `_Unity/`는 HTML 프로토타입·문서·원본 아트를 보관하는 작업공간이며 Unity로
> 열지 않는다.

> 보일러플레이트가 있는 프로젝트라면 이 파일은 **게임 폴더 안**에 있다.
> 루트 `CLAUDE.md`(보일러플레이트 규약)와 함께 읽되, **이 폴더 안에서는 이 파일이 우선**한다.
> 경계 판별 기준은 `HANDOFF.md` §2-1 — *"다음 게임이 고치지 않고 쓸 수 있는가."*
> 시뮬레이션 계층(`Fish` · `PathEvaluator` · 접근 방식 · `Bobber`)은
> **매니저를 부르지 않는다.** 헤드리스 밸런스 검증과 결정론이 거기에 걸려 있다.

모바일 방치형 낚시 게임. Unity URP(3D 메시 + 직교 카메라), 탑다운 시점.
**어종 5종: 멸치 · 연어 · 만새기 · 오징어 · 참치.**
**필수 조작은 "찌를 어디에 놓을까" 하나뿐이고, 손을 놓아도 자동으로 잡힌다.**
목표는 "멍하니 보고만 있어도 재밌는 것"이다.

## ⚠️ 절대 임의로 바꾸지 말 것

아래는 전부 **의도적으로 그렇게 짠 것**이고, 이유가 문서에 있다.
"버그처럼 보이는데 고칠까요?"가 아니라 **먼저 물어볼 것.**

| 코드에서 이상해 보이는 것 | 실제 이유 |
|---|---|
| `Fish` 가 위치와 회전을 절대 분리하지 않고 `Steer()` + `Advance()` 로만 움직임 | 각도를 목표로 보간하면 속도가 0에 가까울 때 **제자리에서 빙글 돈다.** 미사일처럼 선회율 제한 + 머리 방향 전진이어야 한다 (§5-3) |
| 스폰 시 `_t = 0f` — 랜덤이 아님 | 경로가 `origin + dir*speed*t` 라서 t=20이면 **스폰 순간 이미 24유닛 진행한 화면 밖**에 나타난다. 개체 변화는 origin과 위상이 담당한다 (§11-1) |
| `PathEvaluator.WrapOrigin` 이 목표 좌표를 직접 지정 (누적 가산 아님) | `origin += W` 방식은 한 프레임에 여러 번 발동해 물고기를 날려버린다 (§11-1) |
| 놀람 오프셋에 상한이 두 겹 (`StartleOffsetCap`, `MaxPathOffset`) | 없으면 연속 재착수 시 물고기가 화면 밖으로 날아간다. 실제로 x=41까지 나갔다 |
| 재착수 페널티가 **반경은 1.35배까지만**, 지속은 2.5배 | 반경을 2.5배로 키우면 참치 놀람 반경이 7.5유닛(연못 폭의 절반)이 된다 |
| 참치(`tuna`)의 `lureChance = 0` | **의도.** "작은 놈은 물장구에 몰리고 참치은 조용해져야 온다"가 이 게임의 규칙이다 (§5-0) |
| 참치 `approachSpeed = 0.5` (매우 느림) + `minNoticeRadius = 3.2` | 접근 시간(6~11초)이 낚는 주기(약 7초)보다 길어야 "잡을수록 참치이 멀어진다"가 성립한다. 올리면 규칙이 무력화된다 (§1-3) |
| 자동 회수가 기본이고 탭이 선택 | 손을 놓아도 돌아가는 게 이 게임의 기본 상태다. 탭을 필수로 만들면 기획이 뒤집힌다 (§1-4) |
| 리소스가 **3D 메시 + 정점 휨** (v2.0 확정) | 스프라이트 쿼드는 정점이 4개뿐이라 굽힐 수가 없어서 UV 왜곡이라는 우회로를 썼었다. 그건 전단이지 굽힘이 아니다. 2D 로 돌아가면 **선회 시 몸이 휘는 것을 잃는다** (아트가이드 §3) |
| 텍스처가 0장, 정점 컬러 | UV·텍스처·본·애니메이션 클립 전부 없다. 어종 추가는 파라미터 딕셔너리 한 개 |
| 지느러미 밑동이 **선분** (점 아님) | 점 하나로 붙이면 몸통에서 나오는 부분이 서브픽셀로 얇아져 **떨어져 붙은 것처럼 보인다.** 붙어 있는데 안 붙어 보이는 종류의 버그 |
| 가슴지느러미가 **꼬리의 절반 이하** | 키우면 꼬리와 실루엣이 경쟁해서 "지느러미가 여러 개"로 보인다. 꼬리가 유일한 큰 요소다 |
| 눈 원반이 **위를 향해 눕혀져** 있음 | 표면 법선에 맞춰 세우면 위에서 볼 때 몸통에 잘려 초승달이 된다. 꼬리지느러미를 눕힌 것과 같은 의도적 거짓말 |
| 스프라이트를 **모델에서 굽는다** | 2D 예비안은 별도 아트 파이프라인이 아니라 `fishgen.py --mode sprites` 다. 그래서 3D와 2D가 어긋날 수 없다 |
| 도착했는데 자리가 차 있으면 **줄 서지 않고 떠남** | 대기열은 화면만 어지럽히고 플레이어 판단에 아무것도 안 보탠다. 두 방식 다 시도해보고 내린 결론 (§5-2) |
| 유인에 "최소 1마리 보장"이 있음 | 조작에 대한 응답이 확률이면 아무 반응 없는 착수가 생기고, 그게 '먹통'으로 읽힌다 (§5-0) |
| 유인 피로도(2.5초 내 재착수 시 55%까지 감쇠) | 없으면 "빨리 잡을수록 유인이 자주 발동"하는 복리가 생겨 탭이 사실상 의무가 된다 |
| 획득 시 집계가 **0.85초 뒤**(비행 도착 시)에 오름 | 잡자마자 숫자를 올리면 비행이 장식이 된다. 비행이 결과를 실어 날라야 보상의 리듬이 생긴다 (§6-5) |
| `PlayerData` 가 점수를 저장하지 않음 | 인벤토리로 점수는 계산되지만 그 반대는 안 된다. 후속 납품·강화가 붙을 때 마이그레이션이 없다 (§8) |
| 선회율을 직접 안 주고 **ω = v / R_min** 으로 뽑음 | 각속도를 직접 주면 느린 놈은 제자리에서 돌고(반경 몸길이의 3.5%) 빠른 놈은 소용돌이를 돈다. 반경을 정하고 각속도를 뽑아야 둘 다 사라진다 (§5-3) |
| 목표에 가까울수록 **속도를 깎음** (속도 적합) | `R = v/ω` 라 빠를수록 크게 돈다. 연어 돌진 반경 1.36유닛 > 도착 판정 0.35 → 영원히 맴돈다. 선회율을 올리면 팽이가 되므로 반대로 감속시킨다 |
| 그림자가 3D 복제본이 아니라 **납작하게 눌린 실루엣** | 3D로 두면 그림자의 지느러미가 몸통을 뚫고 올라와 파란 구멍처럼 보인다 |
| 메시의 **머리가 +X** | `rotation.z = heading` 이 +X 를 진행 방향에 맞춘다. 뒤집으면 꼬리가 앞장서서 헤엄치는데 **정지 이미지로는 안 보인다** |
| 선회율·속도를 **평활화한 뒤** 꼬리에 물림 | 둘 다 프레임 차분이라 그 자체로 떨린다. 그대로 물리면 꼬리가 '퍽퍽' 끊긴다 (변화 RMS 0.027 → 0.007) |
| 접근 방식 속도 배율의 **하한 0.85** | 배율은 어종 `approach` 에 곱해진다. 참치은 0.5라 0.55배를 곱하면 접근이 20초를 넘어 **아예 안 잡힌다** (§5-6) |
| `School` 이 타입이 아니라 **변형자** | 어느 운동 법칙 위에도 얹힌다. 추종자는 리더를 **종 이름으로 찾으면 안 된다** — 무리 어종이 둘이면 엉킨다 (§4-1) |
| 무리/독립이 **개체** 단위 | 멸치도 15%는 혼자 다니고 연어도 30%는 둘셋이 몰려다닌다. 어종 단위로 만들면 화면이 죽는다 (§4-4) |
| 파동의 `waveLag`·`waveExp` 가 **어종 SO 값** (머티리얼 프로퍼티 아님) | 상수로 박으면 오징어가 민물장어처럼 굽이친다. 외투막은 파동이 아니라 **통째 요동**이어야 한다. `MaterialPropertyBlock` 으로 주입 — 머티리얼을 어종마다 복제하면 SRP 배칭이 깨진다 (아트가이드 §2-6) |
| `fishgen.py` 의 `bend_y()` 와 셰이더가 **같은 식** | 스프라이트를 굽는 쪽과 3D 를 굽히는 쪽이 어긋나면 fallback 전환 순간 움직임이 달라진다. 한쪽만 고치지 말 것 |
| 파동에 `waveHinge` 가 있고 오징어는 **0.95** | `swim` 은 u=0 에서 항상 0 이라, 몸통이 강체인 오징어는 **주둥이를 축으로 도는 지렛대**가 된다(메트로놈). hinge 앞은 정확히 0 이어야 한다. 물고기는 0 이라 식이 예전과 동일 (아트가이드 §2-6) |
| Hover-Dash 가 **부유가 아니라 돌진 중에** 방향을 튼다 | ω = v/R 이라 부유 속도(0.20)로는 못 돈다. 예전엔 부유 중 67°/s 를 허용해 **반경이 몸길이의 6%** — 실측 선회 프레임의 99.6%가 제자리 회전이었다 (§5-3) |
| 오징어 다리 8가닥의 `uTip` 이 **가닥마다 다름** | 같으면 8개가 같은 위상으로 움직여 갈퀴 하나로 보인다 |
| glb 의 **UV0=(aU,aSeed) · UV1=(aRip,0)** | glTF 는 임의 정점 속성을 안 실어준다. v2.0 까지 glb 에 `aU` 가 아예 없어서 **휨 셰이더가 원리적으로 못 돌았다** — 렌더는 되니까 한참 뒤에야 발견된다. 유니티에서 `uv`/`uv2` 로 받는다 (아트가이드 §2-8) |
| 휘어야 하는 부속은 전부 **분절** (다리 7 · 오징어 지느러미 12) | 면 한 장이면 **휠 수가 없고 꺾이기만 한다.** 다리가 '갈퀴'로, 지느러미가 '연'으로 보이던 원인. 진폭·위상을 아무리 만져도 안 고쳐진다 — 정점이 없는 건 파라미터로 못 만든다 |
| `uJet`(외투강 충전)이 **부유 중 서서히 차오름** | 값이 아니라 **차는 게 보이는 것**이 요점. 돌진 예고가 공짜로 생긴다. 빠르게 채우면 예고가 사라진다 |
| 가슴지느러미 젓기 세기가 **개체 자신의 평균 속도** 기준 | 어종 `approach` 를 기준으로 쓰면 참치은 접근 속도(0.5)가 순항 속도(2.1)보다 느려서 **영원히 지느러미를 접고 있다**. 개체 평균이면 어종별 튜닝이 아예 필요 없다 (아트가이드 §2-6-B) |
| 놀람이 **속도 증가가 아니라 C-스타트** | 그냥 빨라지기만 하면 '재생 속도를 올린 것'으로 보인다. 접히는 전반부는 안 나가고 펴지는 후반부에 튕겨나가야 한다. 그래서 `turnBend` 클램프가 ±0.40 이 아니라 ±0.60 |
| 프레임 루프의 `dt` 에 **0 하한** | 첫 프레임에 `t < last` 면 dt 가 음수 → 평활 계수 음수 → `vSm` 음수 → `pow(음수, 1.7)` = **NaN**. `clamp` 는 NaN 을 안 걸러준다. 지느러미가 첫 프레임부터 **영구히 멈춘다.** 값이 0 도 아니라 로그로도 안 잡힌다 |
| 입 벌림이 **없는 것은 의도** | 연못 시점에서 물고기 한 마리가 90px 라 입은 1~2px 다. 입이 보이는 곳은 획득 연출(§6-5)뿐이고 거기서 다루는 게 맞다 |
| 경로의 `anchor()` 가 **현재 위치가 궤도 위에 오도록 역산** | 위상을 랜덤으로 고르고 중심을 그대로 두면 `pos()` 가 딴 데를 돌려준다 → **순간이동**. 참치(Loop) 실측 4.0~5.5유닛(몸길이의 2.3~3.2배), 연어(Lane) 0.6유닛. 상태가 바뀔 때마다 터진다 |
| 부속(다리·촉완)이 **스스로 젓지 않음** | 사인파로 젓게 하면 꼬리가 여덟 개 달린 물고기가 된다. 늦게 따라오고(`uTurnLag`) 물살에 흩날린다(`uDrift`). 오징어 `waveAmp` 는 그래서 1.70 이 아니라 0.55 |
| 흩날림 식에 **공간 파수**(`- uu*3.4`)가 있음 | 없으면 한 가닥이 휘지 않고 통째로 기울기만 해서 '수수깡'이 된다. **분절만으로는 부족하다** — 변위 식에도 파수가 있어야 휜다 |
| 유영 변위에서 **`swimAt(0.36)` 을 뺌** | 안 빼면 주둥이가 고정축이 되어 몸 전체가 좌우로 까닥인다. 빼면 무게중심이 축이 되고 머리가 꼬리와 반대로 도는데, 그게 실제 물고기다 |
| 지느러미 박자가 **`uTime` 기반** (`uPhase` 아님) | `uPhase` 는 속도 결합이라 빠른 물고기가 지느러미를 '손처럼' 파닥인다 |
| 오징어 `arcBody = 0.22`, `bank = 0.10` | 외투막은 강체다. 선회 호를 몸통에 다 걸면 활처럼 휘고, 물고기처럼 기울면 어색하다 |
| 회피가 **경로 함수가 아니라 오프셋** | Lane/Loop 의 `p = f(t)` 순수성이 헤드리스 검증·결정론의 근거다(§4-1). 놀람과 같은 오프셋으로 얹어야 그게 살아남는다. 감쇠와 상한 필수 (§5-6-B) |
| 회피 벡터가 **합이 아니라 평균** | 합으로 두면 반경이 큰(=덩치 큰) 물고기가 이웃을 더 많이 보게 되어 **제일 많이 비키는 역설**이 생긴다. 실측에서 참치가 가장 크게 밀렸다 |
| 회피는 **앞쪽만**, 같은 무리는 **제외** | 뒤를 피하면 무리 뒤꽁무니가 서로를 밀어낸다. 같은 무리를 피하면 대형(§4-4)과 싸워서 무리가 터진다 |
| Hover-Dash 에 **기분(mood)** 이 있음 | 파라미터만 랜덤이면 '부유-돌진-부유-돌진'이라는 **리듬 자체**가 읽힌다. 부유 시간 편차 2.1배 → **18.2배** (§5-6-C) |
| 다리가 **스프링-댐퍼**로 몸에 반응 | 시간 기반 흩날림만으로는 헤엄을 치든 멈춰 있든 똑같아 '그림이 떠다니는' 느낌이 남는다. ζ≈0.58 — 한두 번 출렁이고 멈춘다 (아트가이드 §2-6-C) |
| 다리 오므리기가 **밑동을 안 건드림** | `mix(1, uArmTuck, min(uu-1,1))`. 밑동까지 모으면 외투막에서 떨어져 보인다 |
| 토막지느러미 색이 **몸 지느러미와 별개** (`finletCol`) | 참치는 여기만 노랗다. 꼬리까지 노랗게 하면 만화가 된다. 크기도 0.021 이하 — 0.040 은 노란 깃발 줄이 된다 |
| 회피가 **적분이 아니라 2단 저역통과** | 적분+감쇠면 피함→멀어짐→감지끊김→되돌아옴 의 **극한 순환**이 생긴다. 게다가 오프셋은 위치를 옮기는데 머리 방향은 **위치 차분**에서 나오므로 작은 떨림이 **증폭**된다 → '드드득'. 실측 각가속도 16~18배, 만새기 선회 반전 1→512회 |
| `Loop.init` 이 중심을 **연못 전체에 흩음** | 한가운데(W/2±1.2)에 몰면 같은 종 둘이 거의 같은 8자를 돌아 계속 겹친다(실측 52%). **회피로는 못 푼다** — 같은 궤도에 갇혀 있으면 밀어내도 다시 만난다 |
| 무리 대형이 **어긋난 쐐기(V)** | 랜덤 극좌표면 두 마리가 같은 자리에 놓이는 걸 막을 방법이 없다. 실측 겹침 60% → **2% 이하** |
| 랩할 때 `px/py` 도 **같이 옮김** | 안 옮기면 그 프레임의 속도 벡터가 연못 폭만큼 튀고 머리 방향이 뒤집힌다. 속도는 클램프하지만 **방향은 클램프가 없다** |
| 어종 색이 **색상 60° 이상 + 명도**로 갈림 | 형태를 아무리 잘 잡아도 색이 비슷하면 연못에서 구분이 안 된다. 큰 종이 전부 어두우니 **밝은 종(멸치)을 하나** 둔다 |
| 크기 과장 **6.1배** (0.42~2.55) | 탑다운은 길이 차이만 읽히고 부피 차이는 안 읽힌다. 실제 비율보다 과장해야 대물이 "어?" 가 된다 |
| 토막지느러미가 **부채꼴** (삼각형 아님) | 뾰족하면 '가시가 줄지어 난 것'처럼 보인다. 바깥 돌출 `len*0.30` 이하 |
| 제트·항력 계수가 **크게** 잡혀 있음 (0.86 / 0.82) | 유니폼이 0~1 로 꽉 차도 진폭이 작으면 **화면에서 5px** 라 없는 것과 같다. 검증은 파라미터 범위가 아니라 **연못 전체 배율에서의 픽셀**로 한다 (아트가이드 §2-6-D) |
| 오므리기 시상수가 **비대칭** (조임 11 / 풀림 3.4) | 돌진이 0.58초인데 시상수가 0.25초면 목표의 70%까지밖에 못 가서 변화가 끝나기 전에 사건이 끝난다 |
| 제트 충전이 **부유 남은 시간의 함수** | 상수로 채우면 부유 내내 통통해서 '부풀었다 = 곧 튄다'는 예고가 성립하지 않는다 |
| 입질 반응이 **물린 순간이 아니라 채는 순간** | 물린 순간에 흩으면 탭하든 안 하든 똑같이 흩어져서 **"탭이 이득"이라는 정보가 0 이 된다.** 놀람 세기는 물린 채 놔둔 시간에 비례 (§5-7) |

**수치를 바꾸는 것도 마찬가지다.** `FishingTuning.cs` 와 어종 SO의 값은
웹 프로토타입에서 세션을 수십 번 돌려 얻은 실측 기준값이다. 감으로 바꾸지 말 것.

## 🔧 생성기를 C# 로 옮길 것 (권장)

메시 형태는 **유니티에서 손으로 고치는 게 아니라 생성기 파라미터로 고친다.**
손으로 고치면 다음 재생성 때 날아가고, 생성기와 애셋이 갈라진다.

지금 생성기는 Blender 파이썬(`Art/fishgen.py`)이고, 같은 로직이 웹 벤치에 JS 로도 있다.
**세 번째 포팅(C#)이 어렵지 않고, 그러면 Blender 의존성이 통째로 사라진다.**

```
지금:  파라미터 수정 → Blender 헤드리스 → glb → 유니티 임포트 → 재생
목표:  파라미터 수정 → 에디터 메뉴 클릭 → 즉시 재생
```

생성기 본체는 순수 수학 150줄(윤곽 → 링 → 쿼드 → 정점 컬러)이다. `Mesh` 로 바로 쓰면 된다.
2D 예비 스프라이트도 유니티에서 직교 카메라 + RenderTexture 로 구우면 Blender 가 아예 필요 없다.

## 🔧 첫 작업: `FishingTuning` 을 `const` → ScriptableObject

C# 의 `public const` 는 **컴파일 시점에 호출부로 박히는 값**이라 런타임에 못 바꾼다.
숫자 하나 고치려면 재컴파일 → 플레이 모드 종료 → 세션 처음부터. **튜닝이 구조적으로 막혀 있다.**

SO 로 바꾸면 **플레이 모드 중에 고친 값이 종료 후에도 남는다**(애셋이라서).
`[Range]` 를 달면 인스펙터 슬라이더가 되고 즉시 반영된다. 기획서 §11-0 참조.

**단, 두 덩어리로 갈라서 만들 것** — 위 "절대 바꾸지 말 것" 표의 값들은
인스펙터에서 **경고색 + 이유 병기**. 전부 슬라이더로 만들면 참치 `approachSpeed 0.5` 는
누군가 반드시 올리고, 그 순간 §1-3 이 죽는다.

## 코드 규약

- 네임스페이스 `Fishing`, 에디터 코드는 `Fishing.EditorTools` + `#if UNITY_EDITOR`
- `dt` 는 항상 `FishingTuning.Dt` (프레임 드랍 시 튀는 것 방지)
- 전역 상수는 전부 `FishingTuning.cs`. 매직 넘버를 코드에 흩뿌리지 말 것
- 궤도 계산은 `PathEvaluator` 의 **순수 함수**로 유지 (결정론 = 나중에 자동낚시·리플레이·시뮬레이션 공짜)
- 물고기 30~50마리 규모다. **DOTS/Job/오브젝트 풀 최적화 불필요.** 조기 최적화 금지
- 주석은 "무엇을"이 아니라 **"왜"** 를 쓴다. 위 표의 항목들은 이미 코드에 이유가 달려 있으니 지우지 말 것

## 현재 상태

**된 것**: 코어 시스템 스크립트 전부 + 셰이더 + 에디터 셋업 자동화 + 플레이스홀더 스프라이트.
**안 된 것**: UI 전체, 사운드 전체, 결과 화면, 세션 종료 후 흐름, 낚시터 이동, 도감 화면.

**단, 이 스크립트들은 유니티 없이 작성되어 컴파일 검증이 안 됐다.** 첫 작업은 빌드를 통과시키는 것이다.

### 다음 순서 (기획서 §12-2)

1. 컴파일 통과 → `Fishing > 1·2·3` 메뉴로 씬 구성 → 재생
2. **셰이더 확인** ← 최우선. 꼬리가 잘리지 않는가, 개체마다 박자가 다른가
3. 손 놓고 90초 — 물고기가 몰려오고 자동으로 잡히는가
4. 획득 연출 — 솟아올라 바구니로 가는가
5. 사운드 → UI/세이브 → 낚시터 2곳

### 미결정 (물어볼 것)

- 화면 방향 가로 vs 세로 (지금은 가로 16×9)
- 화면 고정 vs 스크롤 (고정 권장)

## 검증

**이 게임의 재미는 정지 상태로 검증되지 않는다.** 스크린샷이나 코드 리뷰로 판단하지 말 것.

| 확인할 것 | 방법 |
|---|---|
| 관심 큐가 읽히는가 | 재생하고 **찌 던진 뒤 손 떼고 20초 관찰.** 다가오는 놈과 배회하는 놈이 구분되는가 |
| 밸런스 | 90초 세션 목표: **10~13마리, 40점 근처.** 크게 벗어나면 어종 SO의 `curiosity` 부터 |
| 이동이 자연스러운가 | 제자리 회전이 보이면 §5-3 위반. **오징어의 부유 구간**을 볼 것 — 여기가 제일 잘 터진다(속도가 낮아서). 돌진이 직선이면 호로 바뀌어야 한다 |
| 오징어가 오징어로 보이는가 | 직진할 때 **몸통이 완전한 직선**이고 다리만 흔들리는가. 몸통이 굽이치면 `waveHinge` 가 안 먹은 것 |
| 지느러미가 살아 있는가 | **머무는 물고기**와 **돌진하는 물고기**의 가슴지느러미가 다른가. 둘이 같으면 속도 결합이 안 걸렸거나 NaN 으로 멈춘 것 |
| 순간이동 | 상태가 바뀌는 순간(찌 던지기·회수)에 물고기가 **툭 튀는가**. 튀면 그 경로의 `anchor()` 가 역산을 안 한 것 |
| 다리가 물속에 있는가 | 오징어가 **가만히 있을 때도** 다리가 하늘거리는가. 멈춰 있으면 `uDrift` 가 안 걸린 것. 한 가닥이 S 자로 말리지 않고 통째로 기울면 공간 파수가 빠진 것 |
| 드드득 vs 까닥 | 벤치의 **'좌우 재중심'과 '회피'를 따로 껐다 켜볼 것.** 원인이 다르다 — 까닥은 **휨의 축**, 드드득은 **회피가 위치를 흔들어 머리 방향이 튀는 것** |
| 같은 종끼리 겹침 | 90초 관찰. 겹치면 회피가 아니라 **스폰**을 볼 것 — 같은 궤도에 갇혀 있으면 회피로 못 푼다 |
| 오징어 제트가 보이는가 | **확대하지 말고** 연못 전체가 보이는 화면에서. 부유 끝에 부풀고 돌진에 홀쭉해지는가 (몸통 폭 1.76배 차) |
| 놀랐을 때 | 찌를 물고기 **바로 옆**에 던져볼 것. 몸이 C 로 접혔다 펴지는가, 아니면 그냥 빨라지기만 하는가 |

웹 프로토타입(`Docs/bite-bench.html`)을 브라우저로 열면 **정답 동작**을 볼 수 있다.
유니티 결과가 이상하면 프로토타입과 비교할 것.
