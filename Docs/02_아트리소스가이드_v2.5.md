## 0. 왜 3D인가

판단 근거는 두 가지고, 둘 다 벤치에서 실측했다.

**하나. 생성 복불복이 사라진다.** AI 이미지로 4종을 뽑으면 매번 비율·시점·여백이 흔들리고,
한 마리 고치려면 다시 로또를 돌려야 한다. 모델은 파라미터라 "오징어만 20% 길게"가 한 줄이다.

**둘. 선회할 때 몸이 실제로 휜다.** `Fish.cs` 가 이미 매 프레임 `TurnRateNow` 를 계산한다.
3D 면 그 값으로 몸통을 굽힐 수 있다. **스프라이트로는 원리적으로 불가능하다** —
쿼드의 정점이 4개뿐이라 정점 변위가 아예 동작하지 않는다(그래서 v1.1 은 UV 왜곡이라는
우회로를 썼고, 그건 전단(shear)이지 굽힘이 아니다).

**비용 실측**

| | 값 |
|---|---|
| 삼각형 | 2,080 / 마리 (눈 포함. 해상도 낮추면 900까지) |
| 50마리 총합 | 약 104k tri — 모바일에서 문제 없음 |
| 텍스처 | **0장** (정점 컬러) |
| 애니메이션 클립 | **0개** (셰이더가 굽힌다) |
| glb 4종 | 185KB |
| 새 어종 추가 | 파라미터 딕셔너리 한 개 |

## 1. 파이프라인 — 한 소스, 두 출력

```
fishgen.py  (Blender 4.0, 헤드리스)
   │
   ├─ --mode sheet     검수용 렌더 (탑다운, 물 배경 합성)
   ├─ --mode bend      휨 4단계 렌더 (셰이더 검증용) · `--sp <key>` 로 어종 지정
   ├─ --mode sprites   ★ 2D 예비안 — 유영 1주기를 8프레임으로 굽는다
   └─ stat.py          glb 익스포트 (유니티 임포트용)
```

**스프라이트는 별도 아트 파이프라인이 아니다.** 같은 모델을 위에서 렌더한 것이다.
그래서 3D와 2D가 어긋날 수 없고, 모델을 고치면 스프라이트는 한 번 다시 구우면 된다.

> 어종 정의는 `fishgen.py` 맨 위 40줄이 전부다. 형태를 고치는 데 재생성 로또가 필요 없다.

## 2. 3D 규격 (본안)

### 2-1. 메시

| 항목 | 규격 |
|---|---|
| **앞 방향** | **+X.** `rotation.z = heading` 이 +X 를 진행 방향에 맞춘다 |
| 원점 | 몸 가운데 (머리 끝 아님) |
| 해상도 | 링 40 × 세그먼트 24 (약 2,000 tri) |
| 색 | **정점 컬러.** UV 도 텍스처도 없다 |
| 본 | **없음** |
| 애니메이션 클립 | **없음** |
| 익스포트 | glb (정점 컬러 포함) |

> ⚠️ **앞 방향이 -X 면 꼬리가 앞장서서 헤엄친다.** 그리고 이건 **정지 이미지로는 안 보인다.**
> 검증: x 가 가장 큰 정점의 몸통 파라미터 `u` 가 0(주둥이)인가.

### 2-2. 색 — 텍스처 없이

- **등마루는 진하고 옆구리는 밝게**(카운터셰이딩). 탑다운에서 둥근 느낌은 이게 만든다
- 줄무늬 · 반점은 정점 컬러에 직접 굽는다 (연어 세로 줄, 오징어 색소포 반점)
- 지느러미/다리는 몸통보다 약간 어둡게. **등지느러미 능선만은 등마루와 같은 색** —
  다른 색이면 위에서 '창'처럼 읽힌다

### 2-3. 지느러미는 밑동이 '선분'이어야 한다

> ⚠️ 밑동을 **점 하나**로 두면(삼각형의 꼭짓점 하나만 몸통 안) 몸통에서 나오는 부분이
> **서브픽셀로 얇아져서 떨어져 붙은 것처럼 보인다.** 실제로는 붙어 있는데 안 붙어 보인다.
>
> 밑동은 **몸통을 따라가는 선분**(u0 → u1)이어야 하고, 양 끝점 모두 국소 반폭의
> **0.80배 안쪽**에 있어야 한다. 그래야 지느러미가 몸에서 자라난 것으로 읽힌다.

| | u0 → u1 | 길이 | 뒤로 젖힘 |
|---|---|---|---|
| 연어 | .30 → .44 | .15 | .55 |
| 멸치 | .32 → .44 | .11 | .60 |
| **오징어** (외투막) | **.08 → .54** | .20 | .06 |
| 참치 | .27 → .42 | .21 | .55 |

**그리고 겹침보다 중요한 게 크기 위계다.**

> 밑동을 고치면서 지느러미를 키우면 이번엔 **꼬리와 경쟁**한다.
> 위에서 보면 삼각형이 여러 개 달린 것처럼 읽혀서 "지느러미가 여러 개"로 보인다.
>
> **꼬리가 유일한 큰 실루엣 요소다.** 가슴지느러미는 꼬리 길이의 **절반 이하**,
> 젖힘도 0.45 이하로 둔다. 뒤로 많이 젖히면 꼬리 쪽으로 다가가 실루엣이 뭉친다.

| | 꼬리 길이 | 가슴 길이 | 비율 |
|---|---|---|---|
| 연어 | .22 | .095 | 0.43 |
| 멸치 | .26 | .072 | 0.28 |
| 오징어 | (다리 .40) | .150 | 0.38 |
| 참치 | .28 | .115 | 0.41 |

오징어 지느러미가 유난히 긴 것은 실제로 외투막을 따라 길게 붙은 **능선**이기 때문이다.
짧은 삼각형 두 장으로 만들면 '귀'처럼 보이고, 떨어져 보이는 문제도 여기서 제일 심하게 났다.

같은 이유로 **꼬리지느러미와 오징어 다리도 밑동이 선분**이다 (미병 폭에 맞춰 붙인다).

### 2-4. 눈 (v2.0 추가)

탑다운에서 눈은 물고기 인식의 절반이다. 다만 **크면 즉시 징그러워진다.**

| 규칙 | 왜 |
|---|---|
| **작은 원반 3장**을 얹는다 — 홍채링 → 동공 → 하이라이트 | 링 정점에 색을 칠하면 해상도(세그먼트 24)에 눌려 각진다 |
| 크기는 **국소 반폭의 0.62배 이하**로 클램프 | 절대 크기로 주면 머리에서 실루엣 밖으로 튀어나온다 |
| 원반을 **위로 눕힌다** (법선이 아니라 +Z) | 표면 법선에 맞춰 세우면 위에서 볼 때 몸통에 잘려 **초승달**이 된다. 꼬리지느러미와 같은 의도적 거짓말 |
| **국소 단면의 최고점 위**에 올린다 (`z = h(u) + 0.012L`) | 일부가 몸에 파묻히면 홍채링만 잘려 또 초승달이 된다 |
| 홍채는 흰색이 아니라 **옆구리 색을 밝힌 것** | 대비가 높으면 인형 눈이 된다 |
| 하이라이트는 동공의 0.34배, **바깥쪽으로 치우침** | 이게 없으면 점이 '눈'이 아니라 '반점'으로 읽힌다 |
| 위치는 등마루에서 옆으로 내린 각 `π/2 − spread` | 정면을 향한 한 쌍은 '얼굴'로 읽혀 톤이 깨진다 |

| | 연어 | 멸치 | 오징어 | 참치 |
|---|---|---|---|---|
| u (머리에서) | .180 | .190 | **.84** | .155 |
| spread | .58 | .56 | .70 | .55 |
| 동공 반경 (L 대비) | .029 | .026 | .038 | .023 |

> 오징어의 눈은 **다리 밑동(u≈0.84)** 에 있다. 외투강이 앞서고 머리가 뒤에 있는 구조라 그게 맞다.

### 2-5. 머티리얼 — 툰 2단

```
정점컬러 × 램프(N·L 을 2~3단으로 계단화) → Emission
+ 외곽 어둠(rim): 1 - |뷰공간 노멀.z| 가 클수록 어둡게
```

얇은 지느러미는 **양면 조명**이어야 한다(`gl_FrontFacing` 으로 노멀 뒤집기).
안 하면 뒷면이 새까맣게 나온다.

### 2-6. 휨 셰이더 계약 (기획서 §6-1 대체)

정점 셰이더가 매 프레임 몸통을 굽힌다. **본도 클립도 없다.**

```glsl
uu   = max(aU, 0.0)                       // 0=주둥이, 1=미병, 1.3=꼬리끝
b    = max(uu - uHinge, 0.0)              // 관절 이후의 길이
swim = uAmp * pow(b, uExp) * sin(uPhase - uu * uLag)
arc  = uTurn * (pow(min(uu,1.0), 1.9) + max(uu-1.0, 0.0) * 0.5)
pos.y += (swim + arc) * uLen
// 접선 기울기만큼 노멀도 함께 돌린다
```

| 유니폼 | 어디서 오나 | 기본값 |
|---|---|---|
| `uAmp` | 어종 `waveAmp` × 전역 `WAVE_K` | — |
| `uPhase` | 개체별 위상. 속도가 빠를수록 빨리 진행 | — |
| `uTurn` | **`TurnRateNow` 를 어종 선회율 상한으로 정규화한 값** | — |
| `uLen` | 어종 몸길이 | — |
| `uLag` | 어종 `waveLag` — 몸을 따라 흐르는 **위상 지연** | 2.4 |
| `uExp` | 어종 `waveExp` — **앞쪽이 얼마나 참여하는가** | 1.6 |
| `uHinge` | 어종 `waveHinge` — **파동이 시작되는 지점**(그 앞은 강체) | 0.0 |

**`uLag` / `uExp` 가 왜 어종별이어야 하나 (v2.0 추가)**

이 둘을 상수로 박으면 모든 생물이 "물고기처럼" 헤엄친다. 오징어에서 바로 티가 났다.

| | 큰 값 | 작은 값 |
|---|---|---|
| `uLag` | 파동이 머리→꼬리로 **타고 지나간다** (장어·정어리) | 몸 전체가 **한 덩어리로 함께 흔들린다** (오징어) |
| `uExp` | 앞쪽은 거의 안 움직이고 **꼬리만** 친다 (참치) | 몸 전체가 고르게 참여한다 (오징어) |

**`uHinge` 가 진짜 문제였다 (v2.0 개정).**

`swim` 은 `u=0`(주둥이)에서 항상 0이다. 물고기는 이게 맞다 — 머리가 앞장서고 몸이 따라온다.
그런데 **오징어는 몸통 전체가 강체**라서, 주둥이가 0 이면 뻣뻣한 외투막이 통째로
**주둥이를 축으로 도는 지렛대**가 된다. 메트로놈 바늘이다.

실측(개정 전): 몸통 중앙이 몸길이의 **4.2%**, 외투막 끝이 **8.4%** 흔들리고 있었다.
"머리는 가만있고 꼬리만 움직인다"는 정확히 이 현상이다 — 축이 주둥이에 박혀 있었다.

`waveHinge = 0.95` 를 주면 aU 0~0.95(외투막 전체)가 **정확히 0** 이 되고
관절이 다리 밑동에만 남는다. 물고기는 `waveHinge = 0` 이라 **식이 예전과 완전히 동일**하다.

| | 몸통 중앙 | 끝(꼬리/다리끝) |
|---|---|---|
| 연어 | 4.2% | 18.4% |
| 멸치 | 2.5% | 11.7% |
| 참치 | 5.9% | 28.0% |
| **오징어** | **0%** | **17.0%** |

> `waveAmp` 는 **관절 이후 길이 기준**이다. hinge 를 준 어종은 가용 구간이 짧아지므로
> 같은 흔들림을 얻으려면 값이 커진다(오징어 1.70). 숫자만 보고 "과하다" 판단하지 말 것.

**다리 8가닥은 위상을 어긋내야 한다.**

`uTip = 1 + len·long·1.15 × (0.82 + 0.30·|t|)` — `t` 는 중앙 0, 바깥 ±1.
안 어긋내면 8가닥이 완전히 같은 위상으로 움직여 **갈퀴 하나처럼 보인다.**
바깥 다리일수록 지렛대가 길어 더 끌린다는 뜻이라 물리적으로도 맞다.

> ⚠️ **`WAVE_K` 를 빼먹지 말 것.** 꼬리 정점의 `aU` 가 1을 넘기 때문에(끝일수록 크게 휨)
> 명목 진폭을 그대로 넣으면 꼬리가 몸길이의 35%씩 휘둘러 바나나가 된다.
> v1.1 의 UV 왜곡에서 이미 밟았던 함정을 3D 에서 또 밟았다. **0.40 이 실측값.**

> ⚠️ **`fishgen.py` 의 `bend_y()` 와 이 셰이더는 같은 식이어야 한다.**
> 스프라이트를 굽는 쪽(파이썬)과 3D 를 굽히는 쪽(GLSL)이 어긋나면
> **fallback 으로 전환하는 순간 움직임이 달라진다.** 한쪽만 고치지 말 것.

**기존 `FishWave.shader`(v0.3) 와의 대응**

이름만 다를 뿐 이미 있는 프로퍼티다. 새로 만들지 말고 이름을 맞춘 뒤 **머티리얼이 아니라
어종 SO 에서 주입**하도록 바꾼다. 지금은 머티리얼 프로퍼티라 어종별로 다르게 줄 수가 없다.

| v0.3 셰이더 | v2.0 계약 | 해야 할 일 |
|---|---|---|
| `_Falloff` (Tail Falloff Power) | `uExp` | 어종 SO 값으로 `MaterialPropertyBlock` 주입 |
| `_BodyPhase` (Phase Shift Along Body) | `uLag` | 〃 |
| `_Amp` | `uAmp` | 〃 (× `WAVE_K`) |

> 머티리얼을 어종마다 복제하지 말 것 — SRP 배칭이 깨진다. `MaterialPropertyBlock` 이면 유지된다.

### 2-6-B. 생동감 채널 (v2.1 신설) ★

여기까지가 "몸이 휜다"였다. 그것만으로는 **그림이 떠다니는 느낌**이 남는다.
아래 다섯은 전부 *움직임을 추가*하는 게 아니라 **원래 움직였어야 할 것이 굳어 있던 것**을 푼 것이다.

| 채널 | 무엇 | 어디서 |
|---|---|---|
| `aSeed` (정점 속성) | 요소별 난수 0..1. **몸통은 0** | 다리·부속마다 다른 위상·진폭 |
| `aRip` (정점 속성) | 지느러미 막의 바깥쪽 정도 0..1 | 지느러미 물결. 밑동(0)은 안 움직인다 |
| `uSpread` | 시드 → 위상 오프셋 배율 (오징어 5.4) | 어종 SO |
| `uJet` | 외투강 충전량 0..1 | 부유 중 상승, 돌진 중 급강하 |
| `uRoll` | 뱅킹 각(라디안) | 평활화한 선회율 / 어종 상한 × `bank` |
| `uRip` | 지느러미 진폭 × **젓기 세기**(속도 반비례) | 어종 SO × 런타임 |
| `uRipW` | 지느러미 **공간 파수**. 이 하나로 동작이 갈린다 | 어종 SO |
| `uRipF` | 지느러미 박자 — **꼬리 박자와 분리** | 어종 SO |
| `uTime` | 전역 시간 + 개체 오프셋 | 런타임 |
| `uDrift` | 부속이 물살에 흩날리는 양 | 어종 SO |
| `uTurnLag` | **조금 전의** 선회값 — 부속이 이걸 따라온다 | 런타임 |
| `uArcBody` | 몸통이 선회 호에 참여하는 정도 (오징어 0.22) | 어종 SO |
| `uArmSwing` · `uArmTuck` | 다리 관성 · 항력 (§2-6-C) | 런타임 |
| `uPivot` | 휨의 회전 중심 (0.36 = 무게중심) | 상수 |

```glsl
// 제트 — 몸통(uu<=1)만. 다리는 물을 담지 않는다
float mantle = 1.0 - smoothstep(0.86, 1.02, uu);
float fill   = (uJet - 0.5) * mantle;
p.yz *= 1.0 + fill * 0.34;      // 차면 통통, 뿜으면 홀쭉
p.x  *= 1.0 - fill * 0.10;

// 뱅킹 — 단면을 통째로 기울인다 (노멀도 같이)
p.yz = mat2(cos(uRoll), -sin(uRoll), sin(uRoll), cos(uRoll)) * p.yz;

// 지느러미 물결 — 막의 바깥쪽일수록 크게, 몸을 따라 흐른다
p.x += uRip * aRip * sin(uPhase * 1.55 - uu * 11.0) * uLen;

// 유영 — 요소별 위상/진폭
float ph   = uPhase + aSeed * uSpread;
float gain = 1.0 + (aSeed - 0.5) * 0.62 * step(0.001, aSeed);
float swim = uAmp * pow(max(uu-uHinge,0.0), uExp) * sin(ph - uu*uLag) * gain;
```

**`uRipW` 하나로 두 가지 전혀 다른 동작이 나온다.**

| `uRipW` | 결과 | 누구 |
|---|---|---|
| 11.0 | 파동이 막을 **타고 흐른다** | 오징어 외투막 |
| 0.0 | 막 전체가 **한 몸으로 앞뒤로 젓는다** | 물고기 가슴지느러미 |

가슴지느러미는 물고기에서 꼬리 다음으로 **계속 움직이는 부분**이다.
이게 멈춰 있으면 아무리 꼬리를 잘 흔들어도 '떠 있는 그림'으로 읽힌다.

**젓기 세기는 속도에 반비례한다 (런타임).**

```
r    = max(0, vSm) / max(0.35, vAvg)     // vAvg = 그 개체의 아주 느린 평균 = 순항 속도
fan  = clamp(1/(1 + 0.55·r^1.7), 0.12, 1.0)
uRip = 어종 finRipple × fan
```

느릴수록 크게 젓고 빠를수록 몸에 붙인다. 덕분에 **'머무는 중'과 '내달리는 중'이
지느러미만 봐도 구분된다.** 실측(찌를 던져 돌진을 섞은 50초):

| | 느릴 때 | 빠를 때 |
|---|---|---|
| 연어 | 0.86 | 0.53 |
| 멸치 | 0.85 | 0.56 |
| 오징어 | 0.94 | 0.41 |
| 참치 | 0.92 | 0.34 |

> ⚠️ **기준을 어종의 `approach` 로 잡으면 안 된다.** 참치은 접근 속도(0.5)가
> 순항 속도(약 2.1)보다 **느리다**(§1-3의 그 값). 그걸 기준으로 쓰면 참치은
> 영원히 지느러미를 접고 있게 된다 — 실측에서 항상 0.12(하한)였다.
> **개체 자신의 느린 평균**을 기준으로 삼으면 어종별 튜닝 자체가 필요 없다.

**부속은 스스로 젓지 않는다 — 끌려오고 흩날린다 (v2.2) ★**

다리·촉완을 `sin(uPhase - u·uLag)` 로 젓게 하면 **꼬리가 여덟 개 달린 물고기**가 된다.

| 무엇 | 어떻게 |
|---|---|
| **늦게 따라온다** | `mix(uTurn, uTurnLag, smoothstep(0.98,1.35,uu))` — **지금이 아니라 조금 전**의 선회 |
| **물살에 흩날린다** | `uDrift` — **시간 기반**. 가만히 떠 있어도 하늘거린다 |
| 스스로 젓는 양 | 오징어 `waveAmp` **1.70 → 0.55** |

```glsl
float da    = max(uu - 1.0, 0.0);
float drift = uDrift * step(0.001, aSeed) * da
            * ( sin(uTime*0.63 + aSeed*17.0 - uu*3.4)
              + 0.55*sin(uTime*1.07 + aSeed*29.0 - uu*6.1) );
```

> ⚠️ **공간 파수(`- uu*3.4`)가 핵심이다.** 없으면 한 가닥이 **휘지 않고 통째로 기울기만** 한다 —
> 그게 '수수깡'의 정체다. **분절만으로는 부족하고 변위 식에도 파수가 있어야** 휜다.

**몸이 주둥이를 축으로 흔들리고 있었다 (v2.2) ★**

`swim` 은 `u=0` 에서 항상 0 이라 **주둥이가 고정축**이고 몸 전체가 거기 매달려 까닥인다.
실제 물고기는 무게중심을 축으로 젓고 **머리는 꼬리와 반대로 살짝 돈다**(head yaw).

```glsl
float swim = swimAt(uu, aSeed) - swimAt(uPivot, 0.0);   // uPivot = 0.36
```

| | 주둥이 | 몸통 중앙(0.36) |
|---|---|---|
| 이전 (주둥이 축) | 0% | 2.5~3.5% |
| **이후 (무게중심 축)** | 2.5~3.5% | **0%** |

**지느러미가 '손처럼' 파닥이던 것 (v2.2)** — 박자를 `uPhase`(꼬리 박자)에 물려놨던 게 원인.
`uPhase` 는 **속도 결합**이라 빠른 물고기일수록 미친 듯이 파닥인다.
`uTime * uRipF` 로 떼어내고 진폭도 낮췄다 (진폭 3.1배 ↓, 박자 4.3배 ↓).

**오징어 선회 (v2.2)** — 외투막은 강체인데 선회 호가 몸통 전체에 걸려 활처럼 휘고 있었다.
`uArcBody` 로 몸통 참여도를 낮춘다(오징어 **0.22**, 물고기 1.0). 뱅킹도 0.30 → **0.10**.

### 2-6-C. 다리의 관성 — 스프링-댐퍼 (v2.3 신설) ★

v2.2 의 흩날림은 **시간 기반**이라 헤엄을 치든 멈춰 있든 똑같았다. 가만히 있을 때는
맞는데 움직일 때 **그림이 떠다니는** 느낌이 남았다.

다리는 물속에 매달린 질량이다. 몸이 옆으로 가속하면 뒤로 쏠렸다가
**넘어갔다 흔들리며 잦아든다.** 그게 감쇠다.

```
aLat  = vSm · turnSm                       // 구심 가속 = v·ω
armA  = -K·armX - C·armV + aLat·gain       // K=30, C=6.4 → ζ≈0.58
armV += armA·dt ;  armX += armV·dt ;  clamp(±0.55)
```

| 유니폼 | 무엇 |
|---|---|
| `uArmSwing` | 적분한 `armX`. 끝일수록 크게, 가닥마다 위상을 어긋내서 |
| `uArmTuck` | **항력**. 빠를수록 다발이 유선형으로 모이고 느릴수록 벌어진다 |

> ζ ≈ 0.53 은 **한두 번 출렁이고 멈추는** 값이다. 1 이상이면 꿀 속이고 0.2 이하면 영원히 떨린다.

### 2-6-D. 채널이 '도는 것'과 '보이는 것'은 다르다 (v2.5) ★★

제트와 다리 항력을 넣고 **유니폼이 0.003 → 0.999 로 꽉 차는 것**까지 확인했는데,
실제로는 **아무것도 안 보였다.** 로그만 보면 완벽했다.

이유는 단순하다. 진폭이 작았다.

```
단면 배율 = 1 + (uJet-0.5)·0.34      → 0.83 ~ 1.17 (±17%)
오징어 반폭 0.130 → 총폭 0.216 ~ 0.304 유닛
연못 배율(1유닛 ≈ 64px) 에서  →  14px ~ 19px
```

**0.45초 동안 5px.** 파라미터는 100% 로 흔들리는데 화면에서는 없는 것과 같다.

> ⚠️ **검증 지표는 파라미터 범위가 아니라 '실제 배율에서의 픽셀'이다.**
> 확대해서 재면 안 된다 — **연못 전체가 보이는 화면**에서 실루엣을 재야 한다.
> 물고기가 화면의 2~5% 밖에 안 되기 때문에, 여기서 안 보이면 없는 기능이다.

고친 값과 실측(연못 전체 배율, 실루엣 픽셀):

| | 충전 | 분사 | |
|---|---|---|---|
| 몸통 폭 | 37px | 21px | **1.76배** |
| 길이 | 68px | 72px | 1.06배 (늘어난다) |
| 면적 | 970px | 610px | 1.59배 |

| 값 | 이전 | 이후 |
|---|---|---|
| 제트 단면 계수 | 0.34 | **0.86** |
| 제트 길이 계수 | 0.10 | **0.24** |
| 항력 오므리기 | 0.55 | **0.82** |
| 다리 관성 이득 | 0.45 | **1.5** |

> ⚠️ **시상수도 같이 봐야 한다.** 돌진이 0.58초인데 오므리기 시상수가 0.25초면
> 목표의 70% 까지밖에 못 간다 — **변화가 끝나기 전에 사건이 끝나서** 안 보인다.
> 조이는 쪽은 빠르게(11), 푸는 쪽은 느리게(3.4) 비대칭으로 준다.

**충전은 부유가 끝나갈 때 몰아준다** — 상수로 채우면 부유 내내 통통한 채라
*"부풀었다 = 곧 튄다"* 는 예고가 성립하지 않는다.
`want = (1 - hover/hoverMax)^0.6` 로 **남은 시간의 함수**로 만든다.

> ⚠️ 오므리기는 **밑동(uu=1)을 건드리면 안 된다** — `mix(1, uArmTuck, min(uu-1,1))`.
> 밑동까지 모으면 외투막에서 떨어져 보인다(§2-3 과 같은 함정).

**C-스타트 (도피 반응).**

놀란 물고기는 빨라지는 게 아니라 **몸을 C 로 접었다 펴며 튕겨나간다.**
그냥 속도만 올리면 *"재생 속도를 올린 것"* 으로 보인다.

```
u     = 1 - cst/0.34                                  // 0 → 1
cBend = dir · 0.46 · sin(π · min(u·1.55, 1))          // 접혔다 펴진다
burst = approach · (0.35 + 2.4 · clamp((u-0.28)/0.42, 0, 1))
```

접히는 전반부는 거의 안 나가고 **펴지는 후반부에 튕겨나간다.** 실측 속도 1.2 → 4.5 (3.7배),
굽힘 0.46 (평상시 선회 굽힘 상한 0.40보다 크다 — 그래서 `turnBend` 클램프를 ±0.60 으로 넓혔다).

이건 §5-7(입질 반응)의 놀람과 같은 자리에 쓴다. **찌가 물고기 바로 옆에 떨어졌을 때**가
가장 잘 보이는 순간이다.

**입 벌림은 넣지 않았다 (의도).** 주둥이는 u=0 에서 한 점으로 수렴하는 구조라
입을 만들려면 머리를 갈라야 하는데, **연못 시점에서는 물고기 한 마리가 90px 남짓**이라
입은 1~2px 다. 보이지도 않는 곳에 정점을 쓰는 대신, 입이 실제로 보이는
**획득 연출(§6-5, 물 밖으로 들어올릴 때)** 에서 유니티가 다루는 게 맞다.

**비트 앤 글라이드**는 셰이더가 아니라 런타임이다. `uAmp` 에 포락선을 곱한다 —
가속할 때 크게 치고 정속으로 흐를 때 죽는다. 사인파를 일정하게 돌리면 **메트로놈**이 된다.

> ⚠️ **NaN 은 한 프레임이면 영구히 남는다.**
> 프레임 루프가 `dt = min((t-last)/1000, 0.05)` 였다. 첫 프레임에 `t < last` 가 되면
> **dt 가 음수**가 되고, 평활화 계수가 음수라 `vSm` 이 음수로 튄다.
> 그러면 `pow(음수, 1.7)` = **NaN** 이고, `clamp` 는 NaN 을 안 걸러준다
> (`NaN < a` 도 `NaN > b` 도 false 라 그대로 통과한다).
> 결과: **지느러미가 페이지 로드 첫 프레임부터 영구히 멈춘 채로 남는다.**
> 정지 화면으로는 당연히 안 보이고, 값이 0 도 아니라 로그로도 안 잡힌다.
> → `dt` 는 **0 으로 하한**을 두고, 분수 지수 거듭제곱의 밑은 **음수 방어**할 것.

> ⚠️ **가장 중요한 교훈: 휘어야 하는 것은 반드시 분절해야 한다.**
> 다리도 지느러미도 원래 **면 한 장**(밑동-끝 쿼드 / 삼각형)이었다.
> 정점이 그것뿐이면 **휠 수가 없고 꺾이기만 한다.** 그래서 다리 8가닥이 '갈퀴'로 보이고,
> 지느러미는 아무리 몸이 휘어도 뻣뻣한 연처럼 남았다.
> 진폭·위상을 아무리 만져도 안 고쳐진다 — **정점이 없는 건 파라미터로 못 만든다.**
>
> | | 이전 | v2.1 |
> |---|---|---|
> | 다리 한 가닥 | 쿼드 1장 | **7분절** |
> | 오징어 외투막 지느러미 | 삼각형 1장 | **12분절** |
> | 물고기 가슴지느러미 | 삼각형 1장 | 3분절 |
>
> 삼각형은 마리당 1,507개(오징어 1,652). 예전과 사실상 같다 — **분절은 공짜에 가깝다.**

**측정값**

| | 값 |
|---|---|
| 다리 8가닥의 순간 벌어짐 | 0.92%L → **3.63%L** (`uSpread` 0 → 5.4) |
| 외투막 단면 (충전 ↔ 분사) | 1.15 ↔ 0.83 = **1.38배** |
| 뱅킹 | 최대 43°, 참치 평균 14.7°(항상 선회 중이라) |

> 제트는 **돌진 예고**를 공짜로 만든다. 부유 중 천천히 부풀고 돌진 때 확 꺼지므로,
> 플레이어는 **"곧 튀어나가겠구나"를 보고 안다.** 이게 §5-7(입질 반응)과 같은 종류의 설계다 —
> 정보를 UI 가 아니라 **몸으로** 전달한다.

### 2-8. glb 가 UV 로 셰이더 채널을 싣는다 (v2.1 신설) ★

> ⚠️ **v2.0 까지 glb 에는 `aU` 가 아예 없었다.** 정점 컬러만 들어 있었다.
> 그 상태로 유니티에 임포트하면 **휨 셰이더가 원리적으로 못 돈다** —
> 정점이 몸의 어디쯤인지 알 방법이 없다. 렌더는 되니까 **한참 뒤에야 발견된다.**

glTF 는 임의 정점 속성을 안 실어준다. 확실한 통로는 UV 뿐이다.

| UV 레이어 | x | y | 유니티에서 |
|---|---|---|---|
| `Chan0` (TEXCOORD_0) | `aU` | `aSeed` | `uv` |
| `Chan1` (TEXCOORD_1) | `aRip` | 0 | `uv2` |

`fishgen.py` 는 조립 직전에 `len(chan) == len(verts)` 를 **assert** 한다.
정점을 추가하면서 채널을 빼먹으면 거기서 멈춘다 — 조용히 0 이 들어가지 않는다.

### 2-7. 그림자

- **반드시 납작하게 눌러 수면에 눕힌다** (`scale.z ≈ 0`)
- 3D 복제본을 그냥 아래에 두면 **그림자의 지느러미가 몸통을 뚫고 올라와** 파란 구멍처럼 보인다
- 물고기는 그림자 평면보다 위에 띄운다
- 구역이 아래(깊은 쪽)일수록 오프셋을 크게, 알파를 낮게

## 4. 폐기된 요건 (v1.1 → v2.0)

**아래는 전부 UV 왜곡 셰이더를 떠받치던 목발이었다. 3D 확정과 함께 사라진다.**

| 폐기 | v1.1 이유 | 왜 이제 불필요한가 |
|---|---|---|
| **위아래 여백 30%** (§3-7) | UV 를 세로로 밀어서 꼬리가 잘리는 걸 막으려고 | 정점을 직접 옮기므로 여백 개념이 없다 |
| **Packing Tag 비우기** | UV 가 밖으로 나가면 옆 스프라이트를 샘플함 | 아틀라스 자체가 없다. **오히려 3D 는 배칭이 이득** |
| **Mesh Type: Full Rect** | 같은 이유 | 스프라이트가 아니다 |
| **참치만 2파트(몸통+꼬리)** | 꼬리 지연을 트랜스폼으로 흉내내려고 | 꼬리 지연이 셰이더 안에 있다. **전 어종 1파트** |
| 어종별 스프라이트 픽셀 규격 | — | 픽셀이 아니라 유닛 기준 |

> 2D 예비안으로 돌아갈 경우 위 요건이 **다시 살아난다** — 단, 스프라이트를 모델에서 굽기 때문에
> 여백은 렌더 셀 크기로 자동 보장된다(§3의 셀 크기가 이미 최대 휨을 포함한 값).

## 5. 어종 5종 (v2.4 — 실제 종)

`fishgen.py` 의 `SPECIES` 딕셔너리가 원본이다. 아래는 읽기용 요약.

**색은 넷 중 가장 강력한데, 가장 자주 실패한다 ★**

v2.3 은 멸치·연어·참치가 전부 **푸른 회색**이었다. 형태를 아무리 잘 잡아도 연못에
흩어놓으면 **어느 게 어느 종인지 안 보인다.** 탑다운에서 물고기는 화면의 2~5% 를
차지할 뿐이라 **먼저 색으로 구분되고 그 다음에 형태가 읽힌다.**

> 색상환에서 **최소 60° 이상** 벌리고 **명도도** 갈라라.
> 은백(밝음) → 주홍 → 금녹 → 크림(밝음) → 진남(어두움).
> 인접한 두 종이 같은 색상·같은 명도면 형태가 아무리 달라도 스쳐 지나갈 때 구분이 안 된다.
>
> 큰 어종이 전부 어두우면 **밝은 종을 하나** 둬라. 멸치가 그 역할이다.

**크기 과장** — 0.42 → 2.55, **6.1배**(이전 3.2배).
대물이 나타났을 때 *"크다"* 가 아니라 **"어?"** 가 되어야 한다. 실제 비율보다 과장하는
편이 낫다 — 탑다운에서는 **길이 차이만 읽히고 부피 차이는 안 읽히기** 때문이다.

**탑다운에서 형태를 가르는 건 넷뿐이다**

1. **폭 프로파일** — 멸치는 가늘고, 참치는 럭비공, 만새기는 뒤로 급히 가늘어진다
2. **등지느러미 길이** — 만새기가 등 전체를 덮는 게 가장 확실한 식별자
3. **꼬리 갈라짐** — .62 이상이면 고속종, .26이면 연어과
4. **무늬** — 띠 / 반점 / 없음

> 옆에서 보면 다른 물고기도 위에서 보면 다 비슷하다. **높이(hmax)는 거의 안 보인다.**
> 만새기의 hmax 0.218 은 실제로는 납작하고 높은 몸인데, 탑다운에서는 **폭이 좁은 것**과
> **등지느러미가 긴 것**으로만 읽힌다. 그래서 그 둘에 형태 예산을 몰았다.

**토막지느러미(finlet)** — 참치 뒤쪽의 작은 지느러미. 위에서 톱니 실루엣이라 식별
기여가 크다. 색을 몸 지느러미와 따로 준다(`finletCol`) — 참치는 여기만 노랗다.

> ⚠️ **뾰족한 삼각형으로 두면 '가시가 줄지어 난 것'처럼 보인다.**
> 낮고 넓은 **부채꼴(가리비)** 이어야 작은 지느러미로 읽힌다 —
> 사각형 4점, 바깥 돌출 `len*0.30` 이하, 크기 `len` **0.020 이하**.

**오징어 형태**

- 진행 방향(+X)이 **뾰족한 외투강 끝**. 다리 8가닥이 -X 로 끌린다 (촉완 2개는 1.85배 길게)
- **외투막 지느러미를 앞쪽에 넓게** — 위에서 볼 때 가장 큰 식별 요소
- 외투막은 **강체**(`waveHinge 0.95`). 유영 파동이 몸통에 닿으면 안 된다
- 몸통 움직임은 **유영이 아니라 선회에서만** 나온다 (`arcBody 0.22`)
- 검증: `--mode bend --sp squid` 에서 직진/유영 포즈는 몸통이 직선, 선회 포즈만 휘면 정답
